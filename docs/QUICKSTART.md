# Quickstart

This is the single setup document for taxpert, along with the entire taxpert/form-builder ecosystem. It covers 
running a Form Builder
application with the Taxpert workspace, in Docker or natively, and the commands that
carry a change in one of the shared libraries out to everything that consumes it.

Because there are five repositories involved, each one's README or ONBOARDING.md points to this document as the 
source of truth, rather than repeating any of it.

1. [Prerequisites](#prerequisites), the toolchain each path needs and where the checkouts go
2. [Generating an application](#generating-an-application)
3. [The Docker path](#the-docker-path), where nothing but Docker is installed on your machine

7. [Propagating a change](#propagating-a-change), what to run after editing a library

## Prerequisites

| Tool | Version | Where the version comes from | Docker path | Native path |
|---|---|---|---|---|
| Docker Desktop | Any current release | Compose v2 syntax in every `docker-compose.yml` | Required | Not used |
| cookiecutter | Any current release | `form-builder-template` is a standard cookiecutter | Only to generate an application | Only to generate an application |
| JDK | 21 or newer | `eclipse-temurin:21-jdk-jammy` in the application Dockerfiles and `java-version: '21'` in the generated CI workflow | Not needed | Required |
| sbt | 1.11.4 | `project/build.properties` in every Scala project | Not needed | Required |
| Node | 20 or newer | `node:20-alpine` in Fact Explorer's Dockerfile, `node-version: '22'` in the generated CI workflow | Not needed | Required |
| xmllint | From libxml2 | An application's `make validate-xml` and `make format` call it | Not needed | Required |
| Python and uv | 3.12 or newer | `requires-python = ">=3.12"` in `services/assistant/pyproject.toml` | Not needed | Only for the assistant |
| Ollama | Any current release | Reached on port 11434 by both paths | Only for the AI features | Only for the AI features |

Ollama runs natively on the host in both paths, never in a container. A Linux container Ollama on
macOS runs CPU only and is slow, so the containers reach the host process instead. The assistant
service sets `OLLAMA_HOST: http://host.docker.internal:11434` and declares
`extra_hosts: ["host.docker.internal:host-gateway"]`, which makes that address resolve on Linux as
well as on macOS.

```bash
cd ~
git clone https://github.com/IRS-Public/fact-graph.git
git clone https://github.com/IRS-Public/form-builder.git
git clone https://github.com/IRS-Public/taxpert.git      # optional, for the workspace and the tools
```
None of the three core libraries are on a public artifact registry, so every one of them is resolved from
a local checkout. The paths below are what the defaults in every Makefile, `package.json`,
Dockerfile and cookiecutter answer resolve against.

```
parent/
├── fact-graph/                gov.irs::factgraph, published to ~/.ivy2/local
├── form-builder/              gov.irs::form-builder, published to ~/.ivy2/local
├── taxpert/                   the workspace UI, Fact Explorer and the assistant
│   └── packages/ui/           the npm package an application depends on
├── my-application/            generated by cookiecutter
└── form-builder-examples/     the three reference applications, each one level down
```

## Generating an application

If you are interested in generating a new application from scratch, run:

```bash
cd ~
cookiecutter https://github.com/IRS-Public/form-builder-template    # or a path to a local checkout
```

Answering `yes` to `include_taxpert_workspace`, `include_fact_explorer` and `include_docker` gets
every surface described below. Run cookiecutter from where you want the application to land rather
than from inside a checkout of the template.

Alternatively you can clone the reference applications and follow their READMEs for running one or all of the 
applications natively or in Docker:

```bash
cd ~
git clone https://github.com/IRS-Public/form-builder-examples.git
```

## The Docker path

### Running taxpert

```bash
cd ~/taxpert
make up
```

Every service here is behind a compose profile, so a bare `docker compose up` starts nothing.
`make up` runs both profiles and prints the applications Fact Explorer will discover before it
starts them.

Narrow the profiles with `make up PROFILES=--profile explorer`. `make rebuild` drops the
`chroma-data` volume, which a plain `down` and `up` preserves, so the document index has to be
repopulated afterwards. The assistant's entrypoint does that on the next start when it finds the
collection empty.

#### How Fact Explorer finds an application

Fact Explorer runs in the taxpert stack rather than in an application's, because one instance holds
every application at once. An application living anywhere else registers itself.
Its own `make up` writes a one-service compose fragment into
`taxpert/docker-compose.apps.d/<app_id>.yml` that bind-mounts the repository at
`/apps-external/<app_id>`, and this repository's Makefile passes every fragment in that directory to
`docker compose`.

A symlink into `taxpert/apps/` does not work in the Docker path. A bind mount carries the symlink
itself rather than its target, so the path dangles inside the container and discovery skips the
application with no error. `make apps` prints what each source contributes before every `up`.


### Running an application

```bash
cd ~/my-application
make up
```

The image builds both Scala
libraries inside itself, generates the site, serves it through nginx, and leaves an `sbt ~run`
watcher regenerating it on every edit you make on the host. `make up` also registers the application
with Fact Explorer and starts that container in the taxpert stack, so there is nothing to start over
there first.

| Surface | Address | Requires |
|---|---|---|
| The flow | `http://localhost:<dev_port>/app/<url_segment>/` | Always |
| Author Mode | `http://localhost:<dev_port>/app/<url_segment>/author/` | The API on `127.0.0.1:<author_port>` |
| Browse All and Path Mode | `http://localhost:<dev_port>/app/<url_segment>/all-screens/` | `include_all_screens=yes` |
| Fact Explorer | `http://localhost:5180/fact-explorer/<app_id>` | `include_fact_explorer=yes` and a taxpert checkout |

Note the `http` rather than `https`, and the trailing slash. `dev_port` defaults to 3010 and
`author_port` to 3004, both cookiecutter answers. The Author Mode API is published on
`127.0.0.1` rather than on all interfaces, because it writes to the flow XML and the fact dictionary
in your working tree.

Give the watcher a minute before expecting anything but the flow itself. The image bakes a
production build, which passes no generator flags, and nginx serves that as soon as the container
starts. Author Mode and Browse All are added by the `sbt ~run` watcher on its first pass, so both
return 404 until it finishes. The flow is up immediately either way.

Run `make unregister-explorer` before you delete or move an application repository. A fragment
naming a path that no longer exists fails `docker compose up` for the whole taxpert stack rather
than just for that one application.

### Using an example application

All three share one Docker layout, so `make up` behaves the same in any of them.

```bash
cd ~/form-builder-examples/credit-assistant
make up            # http://localhost:3003/app/eitc/
```

| Application | Address |
|---|---|
| credit-assistant | `http://localhost:3003/app/eitc/` |
| tax-withholding-estimator | `http://localhost:3000/app/tax-withholding-estimator/` |
| benefits-enrollment | `http://localhost:3006/app/benefits/` |

## The native path

### 1. Publish the two Scala libraries


```bash
cd ~/fact-graph && make publish        # sbt compile fastOptJS publishLocal
cd ~/form-builder && sbt publishLocal
```

Fact Graph's `make publish` also produces the Scala.js browser bundle at
`js/target/scala-3.3.6/factgraph-fastopt/main.mjs`, which each application vendors with
`make copy-fg`. Use it rather than a plain `sbt publishLocal` whenever you are setting up to run an
application.

### 2. Set the application up

```bash
cd ~/my-application
make bootstrap
```

`make bootstrap` is the one-time setup on a fresh clone for local builds. It publishes both Scala libraries, runs
both `npm install` steps, and vendors the generated asset mirrors. Running it again later is
harmless.

If the libraries are already published and you only need the JavaScript side, `make ci-setup`
followed by `make copy-fg copy-shared-ui`. 

To install the workspace UI from a taxpert checkout somewhere other than the path the application
was configured with:

```bash
make link-taxpert TAXPERT_UI=/path/to/taxpert/packages/ui
```

It installs with `--no-save`, so the committed dependency keeps naming the conventional location and
the choice stays local to your machine. This target exists in every application, in the template,
and at the root of the examples repository.

### 3. Run it

```bash
make dev            # http://localhost:<dev_port>/app/<url_segment>/
```
What each flag actually does is in
[form-builder's ARCHITECTURE.md](https://github.com/IRS-Public/form-builder/blob/main/docs/ARCHITECTURE.md).
A deployed build passes none of them.

`~run` watches the source tree, so an edit to flow XML, a fact dictionary, a locale or a vendored
asset regenerates the site. Refresh the browser afterwards. There is no hot module reload, because
the output is a directory of static HTML.

### Every application at once

`form-builder-examples` has a Makefile at its root that fans each command out over every application
it finds.

```bash
cd ~/form-builder-examples
make run-all-local    # run everything locally
make run-all-docker    # run everything in Docker
```

### The taxpert workspace UI

```bash
cd ~/taxpert/packages/ui
npm test && npm run lint     # node --test, then eslint. npm run format is eslint --fix
```

From the repository root, `npm test`, `npm run lint` and `npm run format` fan out across
`packages/*` with `--if-present`. They do not reach `services/assistant`, which is Python. Run one
workspace with `--workspace packages/ui`.

### Fact Explorer

```bash
cd ~/taxpert
npm install                                        # once, at the root; it is an npm workspace
cd packages/fact-explorer
FORM_BUILDER_APPS_DIR=~/form-builder-examples npm run build-registry
FORM_BUILDER_APPS_DIR=~/form-builder-examples npm run dev    # http://localhost:5180
```

`npm run build-registry` has to run at least once on a fresh checkout. `public/data/apps.json` is
generated and gitignored, and loading it is the first thing the application does. Both the registry
build and the dev proxy read `FORM_BUILDER_APPS_DIR`, defaulting to `<repo root>/apps`. With no
application there, `build-registry` fails naming the directory it scanned, and the dev server warns
and falls back to the mock fixture.

The dev proxy reaches each application at its `devOrigin`, so leave the application's own `make dev`
running in another terminal.

### The AI assistant (optional)

The AI features need Ollama running on the host and the assistant service up. Two models cover the
defaults in `.env.example`:

```bash
ollama serve                   # keep this running
ollama pull llama3.1:8b        # the LLM_MODEL default, about 4.7 GB
ollama pull nomic-embed-text   # the EMBEDDING_MODEL default, about 274 MB
```

```bash
cd ~/taxpert/services/assistant
make install                   # uv sync --extra dev
cp .env.example .env
make chroma                    # terminal 1, ChromaDB on :8001
make index                     # terminal 2, build the RAG index
make dev                       # terminal 2, uvicorn on :8000 with reload
```

`nomic-embed-text` is required even when `LLM_MODEL` names a hosted provider, because the indexer
and the retriever call Ollama directly rather than going through LiteLLM.

Start an application before `make dev`. The service fetches the fact dictionary over HTTP at
startup from `FACT_DICTIONARY_URL`. Scenario generation additionally reads that application's
`scenarios/` and `flow/` from disk through `SCENARIOS_DIR` and `FLOW_DIR`.


## Environment variables

All are optional, and all belong in the `.env` at the root of the taxpert repository. Every value
has a working default in `docker-compose.yml` or in the service code.

| Variable | Default | What it does |
|---|---|---|
| `TAXPERT_APPS_DIR` | `./apps` | Host directory holding the application checkouts, mounted read-only at `/apps` |
| `TAXPERT_APP_HOST` | `http://host.docker.internal:3003/app/eitc` | How a container reaches your running application, base path included |
| `TAXPERT_FRONTEND_ORIGIN` | `http://localhost:3003,http://localhost:5180` | Comma-separated CORS allow-list for the assistant |
| `LLM_MODEL` | `ollama/llama3.1:8b` | LiteLLM model string. The prefix selects the provider |
| `SCENARIO_LLM_MODEL` | falls back to `LLM_MODEL` | Optional stronger model for `POST /scenario/generate` |
| `EMBEDDING_MODEL` | `nomic-embed-text` | Embedding model for the document index |
| `OLLAMA_HOST` | `http://host.docker.internal:11434` | Where the assistant finds Ollama |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | unset | Required only when `LLM_MODEL` names a hosted provider |
| `TAXPERT_SCENARIOS_DIR`, `TAXPERT_FLOW_DIR` | Credit Assistant's paths under `/apps` | Which application's scenarios and flow XML the scenario generator reads |

## Ports

| Port | What listens | Started by |
|---|---|---|
| 3010 | A generated application, at `/app/<url_segment>/` | `make up` or `make dev` in that application |
| 3004 | The Author Mode API for that application | `make up` or `make dev-author` |
| 5180 | Fact Explorer, one instance holding every application | `make up` in `taxpert` |
| 8000 | The assistant | `make up` in `taxpert`, profile `ai` |
| 8001 | ChromaDB | `make up` in `taxpert`, profile `ai` |
| 11434 | Ollama, always on the host and never in a container | `ollama serve` |
| 5005 | The JVM debug port for an application | `make debug` in that application |

The application port and the Author Mode port are both cookiecutter answers (`dev_port`,
`author_port`). Two generated applications on one machine cannot both hold 3004, so give the second
one a different `author_port`. The generated page tells the browser which port to call through a
`<meta name="form-builder:author-port">` tag.
### Hot reloading

`docker-compose.override.yml` is merged automatically by Compose and adds the live-reload variants.
To ignore it, name the base file explicitly.

| Service | Behavior when you edit source on the host |
|---|---|
| assistant | uvicorn `--reload` restarts on save. `src/` is bind-mounted and the project is installed editable by uv |
| fact-explorer | The image's `build` stage runs `vite` instead of nginx, so edits hot module reload. `packages/ui` is bind-mounted too, so workspace UI edits are live |
| An application in its own stack | An `sbt ~run` watcher regenerates the site. Refresh the browser afterwards |
| An application under the taxpert stack | Nothing there watches one. The apps directory is mounted read-only |

macOS bind mounts do not emit filesystem events, so each watcher runs in polling mode
(`WATCHFILES_FORCE_POLLING` for uvicorn, `VITE_USE_POLLING` for Vite).


## Propagating a change

Nothing watches across repository boundaries. After editing a library, republish or re-mirror it,
then rebuild whatever consumes it.

### After editing `form-builder`

```bash
cd ~/form-builder
sbt test publishLocal
npm test && npm run lint      # the browser assets shipped in the jar
```

| Consumer | What it needs |
|---|---|
| An application running natively | Restart its `make dev`. sbt re-resolves the SNAPSHOT at project load |
| An application running in Docker | `make up`, which passes `--build`. Both Scala libraries are baked into the image's Ivy cache during the build rather than bind-mounted |
| The theme, the flow runtime and the Author Mode editor | Nothing extra. `FormBuilderAssets` extracts them into each site's `resources/vendor/form-builder/` on every build |

### After editing `taxpert/packages/ui`

```bash
cd ~/taxpert && npm test --workspace packages/ui
```

| Consumer | What it needs |
|---|---|
| An application running natively | `make copy-shared-ui` in it, or `make copy-shared-ui` at the root of the examples repository for all of them at once. The dev targets run it before every build |
| An application running in Docker | Nothing. The dev overlay bind-mounts `packages/ui/src` read-only straight over the vendored directory, so an edit is live. Without the overlay, `make up` rebuilds |
| Fact Explorer, natively | Nothing. Vite resolves the package from the npm workspace |
| Fact Explorer, in Docker | Nothing. `packages/ui` is bind-mounted in the dev overlay |

The vendored mirror at an application's `website-static/vendor/taxpert/` is generated and
gitignored. Never hand-edit it, and never re-implement a shared component inside an application.
`make check-shared-ui` fails the build when the mirror has drifted from the source.

### After editing `fact-graph`

```bash
cd ~/fact-graph && make publish     # sbt compile fastOptJS publishLocal
```

| Consumer | What it needs |
|---|---|
| The JVM side of any application or library | Restart sbt, which re-resolves the SNAPSHOT at project load |
| The browser side | `make copy-fg` in each application, which the dev and production targets run first |
| An application running in Docker | `make rebuild`. Both libraries come from the image's own Ivy cache |

Scala.js compilation is not byte-reproducible, so `factgraph-3.1.0.js` and `main.mjs.map` can change
after `make publish` even when no Fact Graph source did. Those diffs do not need to be committed.

`make copy-fg` prints a message and moves on when it finds no build at `../fact-graph/js/target/`.
All three example applications commit their `factgraph-3.1.0.js`, so they fall back to that bundle
and a fresh clone has a working engine in the browser with no Fact Graph checkout at all. The Scala
side is the part that still needs one.

### After editing an application's flow, facts or locales

The `sbt ~run` watcher regenerates the site. Refresh the browser. Fact Explorer needs
`npm run make-fgm` to pick the change up.

### After editing a `fact-explorer.app.json` descriptor

There is nothing to build. Restart the `fact-explorer` container, or re-run
`npm run build-registry` natively.

## Regenerating derived artifacts

Several directories and files are generated, gitignored, and stale until something regenerates them.

| Command | Where | Regenerates | Run it when |
|---|---|---|---|
| `make copy-fg` | An application | `website-static/vendor/fact-graph/factgraph-3.1.0.js` | After `sbt fastOptJS` in `fact-graph`. Runs automatically before every dev and production target |
| `make copy-shared-ui` | An application | `website-static/vendor/taxpert/` from `node_modules/taxpert/src` | After any change under `packages/ui/src/`. Also runs automatically before every dev and production target |
| `make copy-uswds` | An application that vendors USWDS from npm | `website-static/vendor/uswds-*/` | After `npm install`. Only `benefits-enrollment` and generated applications have this target |
| `make check-shared-ui` | An application | Nothing. It diffs the mirror against the source and fails on drift | Part of `make ci`. Catches a hand-edited mirror or a build that skipped the copy |
| `npm run build-registry` | `packages/fact-explorer` | `public/data/apps.json` from every `fact-explorer.app.json` one level down in the apps directory | On a fresh checkout, and after adding or editing an application descriptor |
| `npm run make-fgm` | `packages/fact-explorer` | `public/data/<app>/form-builder-graph.json` and each scenario index | On a fresh checkout when using `VITE_FGM_SOURCE=real`, and after editing flow or fact XML. Add `-- --app <id>` for one application |
| `make index` | `services/assistant` | The `irs_publications` ChromaDB collection | Once, and after adding documents to `services/assistant/data/`. The Docker entrypoint runs it when the collection is empty |

Never hand-edit anything under a `website-static/vendor/` directory. Those are generated mirrors,
overwritten on the next build, invisible to git, and caught by `make check-shared-ui`.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| sbt reports an unresolved dependency for `gov.irs#form-builder_3` | Form Builder is on no remote, and your local Ivy cache is empty | Clone it and run `sbt publishLocal` |
| sbt reports an unresolved dependency for `gov.irs#factgraph_3` | The same, for Fact Graph | Clone it and run `make publish` |
| `make dev` fails inside `copy-shared-ui` with a missing `node_modules/taxpert/src` | `make ci-setup` never ran, so the `file:` dependency was never installed | `make ci-setup` in that application |
| `make ci` fails with "vendored shared UI is out of date" | The mirror drifted, usually from a hand-edit or a build that skipped the copy | `make copy-shared-ui`, and make the real change in `packages/ui/src/` |
| The workspace shows stale UI after editing `packages/ui/` | The vendored mirror was not regenerated | `make copy-shared-ui` in each application |
| A scaffold change has no effect in any application | `form-builder` was not republished | `cd form-builder && sbt test publishLocal`, then restart the application |
| An edit to `form-builder/` or `fact-graph/` does nothing in a Docker stack | sbt resolves both from the image's own `/root/.ivy2`, which is outside the bind mount | `make build`, or `make rebuild` for a clean start |
| A native dev server prints "Server already running" | A previous `sbt ~run` cycle still holds the port | The message is informational and the existing server keeps serving. Stop the old sbt session to reclaim the port |
| Author Mode sits on "Connecting to the authoring server" | The API is not running, or the page is calling the wrong port | `curl http://127.0.0.1:3004/author/health`, and check that `make dev-author` or `make up` is running |
| Two applications fight over the Author Mode port | 3004 is the default for every generated application | Generate the second one with a different `author_port` |
| An application is registered but its Fact Explorer page is blank | The container reads the application list only at start | Restart the `fact-explorer` container. An application's `make register-explorer` does that for you |
| `docker compose up` fails to bind a port | Something else holds 3000, 3003, 3006, 3010, 5180, 8000 or 8001 | Stop the conflicting process, or run the affected component natively on another port |
| A "from scratch" Docker rebuild still shows old output | Named volumes survive `down` and `up` | `make rebuild`, which runs `docker compose down -v` first |
| `docker compose up` fails for the whole taxpert stack | A fragment in `docker-compose.apps.d/` names a repository that was moved or deleted | Delete that fragment, or run `make unregister-explorer` in the application before moving it |
| Fact Explorer shows "Cannot load the app registry" | `public/data/apps.json` is generated and gitignored | `npm run build-registry` |
| Fact Explorer renders the mock fixture instead of a real application | `VITE_FGM_SOURCE` defaults to `mock` | Set `VITE_FGM_SOURCE=real` in `.env.local` and run `npm run make-fgm` |
| Fact Explorer's application list is empty in Docker | A symlink in `./apps` points outside the mounted directory, so it dangles in the container | Set `TAXPERT_APPS_DIR` to the real parent directory instead of symlinking |
| The chat or scenario generator returns an error | The assistant is unreachable, or Ollama is not running | `curl http://localhost:8000/health`, then confirm `ollama serve` is up on 11434 |
| The assistant logs "indexing failed" and answers without citations | The embedding model is not pulled in the host Ollama | `ollama pull nomic-embed-text`, then restart the assistant |
| Chat answers ignore the IRS publications entirely | The ChromaDB collection is empty because `make index` never ran | Run `make index` in `services/assistant/`, with Chroma and Ollama both up |
| Edits do not trigger a rebuild in Docker on macOS | Bind mounts emit no filesystem events | Already handled by `WATCHFILES_FORCE_POLLING` and `VITE_USE_POLLING` in the overlay. If you added a service, set the equivalent |
